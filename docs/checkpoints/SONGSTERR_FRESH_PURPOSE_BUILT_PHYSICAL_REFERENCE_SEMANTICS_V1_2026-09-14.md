## 1. Purpose

Define the semantic contract for a future purpose-built untouched real-guitar V6 holdout before any hardware purchase, performer contact, calibration capture, holdout recording, model invocation, or correctness exposure.

This document does not select a vendor or sensor implementation. It defines what a qualifying reference system must mean and preserve so later hardware cannot quietly redefine performed truth.

The frozen V6 method/scoring framework remains authoritative. This specification cannot alter Basic Pitch settings, MIDI range, matching tolerances, V6-positive definition, statistical gates, categories, or the exactly-one-correctness-run rule.

## 2. Non-negotiable independence boundary

A future qualifying take has four distinct data domains:

1. **Evaluated DI** — conventional clean magnetic real-guitar DI consumed by the frozen V6 validation path.
2. **Physical pitch-state reference** — independently measured string/fret/contact state used to establish nominal note identity.
3. **Independent event-birth/excitation reference** — independently measured excitation/rearticulation evidence used to distinguish performed note births, especially when pitch state does not change.
4. **Clock/synchronization reference** — common clock or immutable hardware synchronization evidence used to map reference time into evaluated-audio time without examining evaluated-audio content.

The evaluated DI is never an input to reference-event creation, reference-event timing, reference pitch identity, ambiguity resolution, calibration threshold selection, retake decisions, or structural repair.

Basic Pitch/V6/model outputs are never inputs to any reference process.

## 3. Raw truth outranks projections

Raw physical/reference streams are the highest-preservation layer. A derived note-event file is a deterministic projection, not a replacement for raw truth.

For every admitted take, the future manifest must preserve immutable identities/hashes for:

- evaluated DI;
- raw pitch-state stream;
- raw excitation/event-birth stream;
- raw clock/sync stream when separate from the above;
- hardware configuration;
- firmware/software versions;
- calibration artifact(s);
- deterministic reference decoder/state machine;
- deterministic derived reference output.

A derived output is admissible only if it can be regenerated byte-for-byte or semantically identically under a frozen canonical serialization from the bound raw sources and frozen decoder/configuration.

No raw source may be discarded because a MIDI-like projection exists.

## 4. Conceptual raw pitch state

The physical pitch-state plane should expose enough raw state to establish nominal guitar note identity without estimating pitch from evaluated DI.

At minimum, the design must be capable of representing per string:

- `stringId`;
- open/fretted/muted/unknown physical state;
- fret/contact identity or a raw continuous position/contact representation from which a frozen mapping derives fret identity;
- raw state-transition timestamp/tick;
- sensor status/health;
- calibration/configuration identity.

A future deterministic mapping may derive nominal integer MIDI as:

`nominalMidi = calibratedOpenStringMidi + nominalFret`

subject to the frozen tuning/capo rules in the capture plan and the frozen V6 scoring framework.

This nominal MIDI projection does not assert that the sounding fundamental is exactly equal-tempered at all moments. Bends, vibrato, intonation, string stretch, and expressive pitch motion remain richer physical phenomena.

## 5. Conceptual excitation / birth state

A separate independent reference plane must provide evidence that a string/note has been newly excited or rearticulated.

The specification intentionally does not mandate whether that physical signal is derived from picking-hand motion, string-local vibration/force/acceleration, contact dynamics, or another non-evaluated-DI sensor. What matters is that:

- it is physically tied to the performed event;
- it is independent of evaluated DI;
- its threshold/state machine is frozen from non-holdout calibration;
- raw signal/status is preserved;
- it can distinguish repeated same-pitch rearticulation when the pitch-state plane is unchanged;
- it does not use a pitch-transcription model to decide whether an onset happened.

## 6. Reference event conceptual schema

A future deterministic decoder should be able to emit a canonical event object equivalent in meaning to:

- `eventId` — deterministic, unique within corpus;
- `takeId` / `attemptId`;
- `stringId`;
- `birthTick` in the bound reference clock;
- `birthTimeSeconds` after the frozen hardware clock transform, if applicable;
- `birthSourceClass` — e.g. independent excitation, qualifying legato transition, qualifying tap transition;
- `nominalFret` at birth;
- `nominalMidi` under frozen physical mapping;
- `pitchStateSourceIds` — raw physical records supporting identity;
- `excitationSourceIds` — raw physical records supporting event birth, where applicable;
- `techniqueSemanticClass` under the frozen decoder state machine;
- `calibrationId`;
- `referenceDecoderVersion` and immutable blob/configuration SHA;
- raw source SHAs bound at take level;
- optional rich termination/release metadata that is non-authoritative for the currently paused duration question.

Field names may differ in a later schema, but the semantic information and provenance must not be weakened.

`eventId` must be generated deterministically from immutable corpus/take identity plus frozen event ordering or another preregistered collision-resistant construction. It must not depend on model results or manual post-hoc labels.

## 7. Event-birth state-machine principles

A new physical pitch state is not automatically a new note birth, and a new note birth does not always require a new physical pitch state. The decoder therefore requires technique-aware deterministic semantics.

The following rules define the required direction for the future frozen state machine.

### 7.1 Picked note from silence/mute

A qualifying independent excitation associated with a valid physical pitch state creates a new note birth.

### 7.2 Same-string, same-fret reattack

A qualifying independent excitation while the same pitch state remains active creates a **new distinct event**. This is essential for repeated notes and tremolo/repeated picking. Fret-state stability must never collapse repeated attacks into one reference event.

### 7.3 Repeated open-string attack

Same as 7.2. A new qualifying excitation on an open-string state is a new note birth even though the fret state is unchanged.

### 7.4 Fret change with independent pick/excitation

A qualifying excitation plus a new valid physical pitch state creates a new event at the frozen event-birth time determined by the independent reference system.

### 7.5 Hammer-on

A higher-fret transition can create a new event without a conventional pick trigger only when the frozen state machine observes the preregistered physical evidence required to classify that transition as an excitatory hammer-on rather than passive finger placement.

Fret occupancy alone is insufficient unless the future calibration establishes and freezes a physically independent transition signature that reliably represents excitation.

### 7.6 Pull-off

A transition from a higher stopped fret to a lower stopped/open state can create a new event only when the frozen state machine observes the preregistered independent physical evidence required for a performed pull-off. Mere release of a fretting contact is not universally an onset.

### 7.7 Tap

A qualifying tapping transition may create a note birth under a frozen physical rule independent of evaluated DI. The rule must be calibrated and locked before holdout capture.

### 7.8 Slide

A slide must not be converted into a sequence of convenient note births merely because the physical fret/position reference traverses multiple pitch states.

The future preregistration must define the physical rule that distinguishes:

- one continuing event with changing pitch state;
- a genuine rearticulated event during/after a slide.

Intermediate physical positions are preserved in rich raw truth. They become distinct V6 reference births only if the frozen event-birth semantics say a genuine new performed event occurred.

### 7.9 Bend and vibrato

Bend/vibrato state should be preserved when physically measurable. They do not automatically create additional note births.

For the frozen V6 onset/pitch comparison, the event's nominal integer-MIDI identity is determined by the preregistered physical mapping at birth and the frozen scoring framework. This semantics document does not alter V6's existing bend handling or pitch tolerance.

### 7.10 Chords / near-simultaneous polyphony

Each independently supported string/note birth is a separate reference event. A chord is not collapsed into one event.

Reference timestamps retain their independent per-string/event timing. Any later scoring tolerance is the already-frozen V6 tolerance; the reference generator must not quantize chord notes toward a common timestamp for model convenience.

### 7.11 Muting / termination

Muting/release/termination states may be preserved in raw and derived rich reference. They do not create a new note birth unless a separately qualifying physical excitation/event semantic also occurs.

Duration/release correctness remains outside this purpose-built expansion because duration authority is currently paused/unchanged.

### 7.12 Natural decay / sympathetic vibration

A string continuing to vibrate or becoming sympathetically excited must not automatically create a new performed note birth. The frozen event-state machine must require the preregistered physical criteria for intentional/qualifying excitation.

### 7.13 Ghost/dead/percussive notes

These require an explicit pre-capture policy. If the future capture repertoire includes events without a stable pitched identity, the plan must define whether they are excluded from planned V6-reference material by design or represented in a non-V6 rich layer. They may not be selectively removed after observing model results.

## 8. Ambiguous and unknown physical states

The reference decoder must have an explicit `UNKNOWN` / unresolvable pathway rather than guessing from evaluated audio.

Examples include:

- conflicting fret/contact sensors;
- indeterminate string identity;
- missing excitation evidence where the technique semantic requires it;
- invalid clock mapping;
- sensor dropout across an event boundary;
- impossible state transition under the frozen state machine.

If an admitted take contains an ambiguity that violates the frozen structural gate, the take/population fails the reference-blind structural audit according to the preregistered rule. It must not be repaired by listening to or inspecting evaluated DI, viewing a spectrogram, consulting model output, or hand-entering the “obvious” note.

Whether a particular ambiguity is a whole-population blocker or is tolerated under an objective preregistered numeric allowance must be fixed before real capture. No tolerance is chosen from holdout observations.

## 9. Clock semantics

Every raw reference record must carry a clock identity and timestamp/tick sufficient to reconstruct event time under the frozen sync architecture.

Preferred order:

1. common hardware clock/timebase shared by evaluated DI and physical reference;
2. otherwise independent clocks joined only through immutable hardware sync markers captured by both domains.

If a transform is required, its algorithm, units, fit method, marker requirements, residual limits, drift limits, and failure behavior must be frozen on non-holdout calibration before capture.

The future reference decoder is forbidden from using:

- waveform or envelope cross-correlation with evaluated DI;
- spectral similarity;
- audio onset detectors on evaluated DI;
- DTW against evaluated DI;
- Basic Pitch/model activations;
- manual waveform/spectrogram alignment;
- any correctness result.

## 10. Calibration semantics

Calibration is a separate population and can never later become holdout evidence.

Calibration may establish only predeclared physical/reference parameters such as:

- sensor thresholds;
- hysteresis/debounce;
- fret/contact mapping;
- excitation threshold/state classification;
- common-clock/sync decoding;
- clock drift/jitter limits;
- dropout/saturation/stuck-sensor rules;
- technique-specific physical state-machine parameters.

Calibration must be conducted without Basic Pitch/V6/model outcome feedback. The frozen calibration artifact(s) and reference-decoder configuration are hashed and bound into every holdout take/manifest.

Once the first holdout take begins, no calibration or reference-decoder parameter may be changed because of holdout observations. A necessary change requires abandoning the affected holdout population and defining a new prospective population under a new preregistration; it cannot rescue already-observed data.

## 11. Deterministic V6 projection

The physical reference may be richer than the frozen V6 scorer needs. A future deterministic projection layer should reduce rich physical truth to the exact immutable onset + pitch reference consumed by the already-frozen external scoring framework.

The projection must:

- preserve every qualifying reference event exactly once;
- preserve the event's independently established onset time;
- derive nominal pitch solely from the frozen physical pitch-state mapping;
- obey the already-frozen V6 population/scoring scope without changing it;
- never consult Basic Pitch/V6 output;
- never shift, delete, merge, split, quantize, or relabel an event to improve agreement with evaluated DI/model output;
- emit deterministic provenance binding raw source hashes, decoder/configuration SHA, calibration ID, and output SHA.

This document intentionally does not invent a new MIDI-range or matching rule. The existing frozen V6/scoring preregistration remains authoritative.

## 12. Structural invariants before correctness

Before any model/correctness run, a separately preregistered reference-blind structural audit must be able to verify at least:

- all required raw streams exist and match bound hashes;
- decoder/configuration/calibration identities match the frozen plan;
- clock/sync evidence is complete and passes the frozen hardware-only rule;
- event IDs are unique;
- every derived event has valid raw physical provenance;
- no derived event cites evaluated DI/model output as a source;
- no impossible reference state transition remains under frozen semantics;
- no unresolvable ambiguity exceeds its predeclared tolerance;
- no duplicate/effect/channel view is counted as an independent performance;
- admitted roster exactly matches the preregistered population;
- structural anomalies are not manually repaired.

A structural failure closes the affected future candidate population under its frozen gate. It does not authorize a retake after correctness-neutral acquisition QA has already passed.

## 13. Manual intervention policy

No per-event manual truth editing is allowed for the untouched holdout.

Humans may perform only preregistered administrative/provenance actions such as verifying file presence, IDs, rights documents, configuration identity, and objective acquisition-QA statuses.

Humans may not:

- listen and correct event timing;
- inspect a waveform/spectrogram to move an onset;
- add/delete a note because it “obviously” occurred;
- choose among ambiguous physical states using audio;
- reconcile reference/model disagreement;
- repair overlaps/unmatched events after capture;
- downgrade a structural anomaly into a harmless warning after observing it.

## 14. Blinding requirement

During calibration and holdout collection/reference derivation, Basic Pitch/V6/correctness outputs for the future holdout must be inaccessible to the capture/reference decision path.

The strongest implementation is technical separation: the environment/user role performing capture/reference processing has no access path to correctness artifacts until the population is irreversibly bound and passes governance + structural audit.

Procedural declarations alone are weaker and should be supplemented by machine-verifiable provenance where feasible.

## 15. Hardware-neutral acceptance criteria

A future hardware architecture is semantically eligible only if it can plausibly satisfy all of these without using evaluated DI/model inference:

- identify string and nominal fret/pitch state at each reference birth;
- distinguish repeated same-pitch rearticulation;
- support a frozen physical rule for included legato/tap techniques, or prospectively exclude unsupported technique slots before capture;
- provide high-resolution hardware timestamps or synchronizable ticks;
- expose raw sensor/reference data rather than only an opaque corrected note list;
- bind calibration/configuration/firmware identity;
- expose objective health/dropout/saturation/sync status sufficient for frozen acquisition QA;
- permit deterministic offline regeneration of the derived reference;
- preserve richer physical truth even when V6 consumes a simpler onset+integer-MIDI projection.

If a candidate device merely emits post-detection MIDI without sufficient physical/raw provenance to establish these semantics independently, it remains a weak reference lead rather than authoritative truth.

## 16. Explicitly unresolved items

These remain intentionally unresolved until further paper-only design/calibration planning and must not be guessed from future holdout outcomes:

- exact physical sensor class and topology;
- exact excitation/birth sensor mechanism;
- exact common-clock/sync implementation;
- numeric debounce/hysteresis thresholds;
- numeric excitation thresholds;
- drift/jitter/dropout/saturation limits;
- exact legato/tap/slide physical-state classification parameters;
- whether any technique subset must be prospectively excluded due to inability to establish independent truth;
- exact raw event serialization schema.

Every unresolved item must be resolved and frozen prospectively before real holdout capture is authorized.
