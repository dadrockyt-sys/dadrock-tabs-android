## Frozen population rule

The audit population is determined mechanically from the released annotation metadata, not from model output or correctness:

1. Load the released global note-label table described by the dataset (`note_labels.csv` or its unambiguous released equivalent).
2. Admit rows only when the released row itself identifies a **pitched, onset-labeled guitar note** with a finite ground-truth integer `pitch_midi`, finite onset (`onset_label_seconds` and/or `onset_label_samples`), valid `audio_file_path`, and valid `string_number`.
3. Exclude body-percussion rows and any unlabeled/unpitched recordings because they cannot enter the frozen pitch matcher.
4. Do not exclude a valid pitched row because of audio content, Basic Pitch behavior, V6 behavior, confidence, difficulty, player, technique, pitch, timing, or any later correctness observation.
5. The immutable scoring population, if structurally admitted, is every distinct WAV referenced by at least one admitted row and every admitted note row in those WAVs.

If released field names differ only syntactically from the published schema, the audit may bind those exact names and record the mapping. If semantics are ambiguous, fail closed as decision C rather than infer a favorable interpretation.

## Frozen timing/alignment audit

This audit is **reference-blind with respect to V6 correctness**: Basic Pitch and V6 are forbidden.

For each scoring WAV:
- inspect WAV structural metadata and hash exact source bytes;
- verify finite/nonempty decodability without changing source content;
- verify released onset samples/seconds are internally consistent with the WAV sample rate within deterministic rounding tolerance;
- verify each admitted onset lies within its referenced WAV;
- verify annotation ordering/duplicates and record anomalies without silently repairing them;
- inspect a deterministic metadata-derived alignment sample sufficient to establish whether labels are temporally tied to the corresponding recorded note attacks, using only released annotation timing and signal energy/onset structure, never model correctness.

No candidate-specific offset may be learned for rescue. The allowed alignment outcomes are frozen:

- **A:** released timing is structurally synchronized and no systematic correction is required; score released onset timing as-is.
- **B:** a single deterministic annotation-time conversion already implied by released metadata (for example exact sample-rate/unit conversion) is required and can be bound without observing Basic Pitch/V6 correctness; freeze that conversion for every affected file/row.
- **C:** timing/reference/audio pairing is ambiguous, materially unsynchronized, structurally inconsistent, or would require learned/post-hoc correction; reject AG-PT-set and do not score it.

The audit may not invent a lag by optimizing agreement with audio transients. Any unexplained systematic lag requiring estimation is C.
