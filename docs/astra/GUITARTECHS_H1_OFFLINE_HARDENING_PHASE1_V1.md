## Scope and implementation

- New model-free `astra_backend/guitartechs_training_v10/h1_pilot_readiness_v1.py` validates an **independently pinned** Git blob of the accepted primary alignment receipt (`9090d465422ebf5d4fdf170693fe0936934f3073`), exact 256-key set, P1/P2 counts, row key/component/lag identity, canonical prepared filenames and streaming SHA-256 for all prepared feature and label files. The driver checks 192×T feature and 6×T label shapes before training. Computes aligned-key and manifest digests for output receipts. This is a check against the accepted population, not an independent hash of each derived feature fixed before archive preparation.
- An atomic `ScalarProgress` journal updates after every **confirmed** optimizer step, captures current phase and scalar arm summaries and marks ordinary exceptions as failed. It is not a resume state and exports no model weights or captured audio. Journal failure after an optimizer call can make true executed steps exceed last confirmed steps; sudden termination can leave a stale receipt. An exact final execution count cannot be inferred from abrupt termination.
- Core now checks two batches per 20-epoch fold training epoch, consults the **global 160-step guard before each optimizer update**, and notifies the journal after the step. It checks per-capture/aggregate metric finiteness and core event-count schema.
- The driver now trains **both original control folds before either normalized arm**. It still requires the strict original checkpoint state SHA match per fold, and explicitly requires **zero original macro-F1, predicted events AND V4 active runs after pruning**. It stops if either original control fails. Initial model states are compared for paired arms by fold; no seed, decoder, model, loss, threshold, frozen V9 or frozen V8 source/results were deliberately changed.
- The dormant H1 workflow rejects `GITHUB_RUN_ATTEMPT != 1`, requires an exhaustive listed `sourceBlobs` path set (rather than accepting empty/missing source maps), captures scalar partial receipts with `if: always()` when permitted by runner completion, checks the original admission control and removes `*.zip.part` files during ordinary cleanup. **The currently blocked launch JSON is still absent; this workflow was not dispatched.** A new `GITHUB_RUN_ATTEMPT=1` triggered by editing an existing receipt is *not* prevented by this alone; durable one-use consumption is still an open blocker.
